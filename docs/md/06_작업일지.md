- `rpa/run.py`: `collect_live_all()` 이 `asyncio.run` 으로 3곳을 차례로 수집(이벤트 루프가 도는 스레드에서는 별도 스레드)

## Render 502 재발 대응 - RPA 프로세스 격리 (2026-10-28)
- 증상: 배포 후 정상 → 일정 시간 뒤 502, 로그 `Execution of job ... skipped: maximum number of running instances reached (1)`, 빌드 없이 `==> Deploying...`(인스턴스 재시작)
- 원인: 스케줄러가 웹 서버 프로세스 안에서 Chromium 수집 실행 → Render(0.1 CPU·512MB)에서 여행사 접속이 시간 초과로 늘어지며(45초 × 4회 × 여러 페이지) 30분 넘게 종료되지 않음 → 다음 실행 계속 건너뜀, 그동안 Chromium 이 CPU·메모리를 점유해 헬스 체크 실패 → 502 · 재시작 (14:45 이후 수집 로그 0건으로 확인)
- 해결
  - `rpa.run.run_job_isolated()`: 스케줄러·관리자 수동 실행을 **별도 프로세스(nice 10, 독립 프로세스 그룹)** 로 실행, `RPA_JOB_TIMEOUT_SEC` 초과 또는 하위 프로세스(Chromium 포함) RSS 합계가 `RPA_MEMORY_LIMIT_MB` 초과 시 프로세스 그룹 전체 SIGKILL + FAIL 로그
  - 여행사별 `asyncio.wait_for`(RPA_AGENCY_TIMEOUT_SEC), 홈 접속이 Timeout 이면 해당 여행사 즉시 건너뜀, 재시도 횟수 `RPA_RETRIES`
  - 리포트용 Matplotlib·Seaborn 지연 import 로 수집 프로세스 메모리 절약
  - Dockerfile 기본값: 15분 · 여행사당 4분 · 300MB · 재시도 1회 · 페이지 30초
- 검증: pytest 78건 통과(강제 종료 테스트 추가), 로컬 격리 실행 live 79·144·116건

- 서버(`backend/app/security.py` `password_problem`)가 최종 검사: 위반 시 `422 WEAK_PASSWORD` + 안내 문구. 프런트(`frontend/js/auth.js` `NP.passwordChecks`)는 같은 규칙으로 실시간 체크리스트·안전도(위험/보통/안전)·비밀번호 확인 일치 표시.
- 로그인은 규칙을 검사하지 않고 일치 여부만 확인(기존 계정 호환, 실패 시 "이메일 또는 비밀번호가 올바르지 않습니다"로 어느 쪽이 틀렸는지 노출하지 않음). 로그인·회원가입에 Caps Lock 안내 추가.
- 검증: pytest 규칙 테스트 11건 추가, 서버·프런트 규칙 일치 10,011건 비교(불일치 0).

## 누적 방식(72시간 보관) · Render(HTTP) + EC2(Playwright) 혼용 (2026-11-02)

- 512 → 394 감소 원인: 모두투어가 12:30 경 기획전(promotion/1559)을 내림 → 이전 방식(최신 수집에 없으면 즉시 숨김)으로 142건 숨김. 출발 기간이 지난 상품은 0건(대부분 2027-03~06 출발 가능).
- 누적 방식: 수집에서 빠진 상품도 마지막 확인 후 `RPA_RETENTION_HOURS`(72시간) 동안 노출, 출발 기간이 지나면 즉시 숨김. 1시간 이상 지난 정보는 카드에 "N시간 전 확인" 표시. live 가 들어오면 같은 여행사 sample 은 즉시 숨김.
- 엔진 차이의 실제 원인과 조치
  - 하나투어 Playwright 의 카드 id(`productInfo_-18_24300`)는 '노출 순번_기획전번호'로 상품코드가 아님 → 브라우저 세션으로 같은 기획전 데이터(JSON)를 받아 HTTP 와 같은 변환(`hanatour_plan_rows`) 사용
  - HTTP 하나투어 이미지 0% → `mediaList` 에서 이미지 수집(100%)
  - HTTP 노랑풍선 출발일: `11/22,23,28,30,12/2,3` 을 `12` 에서 끊어 11/12 로 해석 → 첫 줄 전체를 공용 파서에 전달(화면 카드와 같은 문구)
  - HTTP 노랑풍선: 서버가 HTML 로 그리는 목록도 함께 파싱
  - 빈 값(이미지·항공사·잔여석)은 기존 값을 덮어쓰지 않음
- 수정 후 같은 시점 비교: 하나투어 186/186(코드 181 일치, 이미지 100%/100%), 모두투어 84/84, 노랑풍선 HTTP 135 / Playwright 137(Playwright 만 2건 - 브라우저에서만 그려지는 국내 목록)
- 같은 테스트 DB 에 Playwright → HTTP 순서로 실제 적재: HTTP 단계에서 하나투어 신규 0·갱신 186, 모두투어 신규 0·갱신 84, 노랑풍선 신규 1·갱신 134 (중복 거의 없음), 서로의 상품을 숨기지 않음
