## Render 502(OOM) 대응 · 발표자료 개선 (2026-10-28)
- 원인: Render 무료 인스턴스(RAM 512MB)에서 Playwright Chromium 이 이미지·CSS·폰트까지 받으며 메모리 초과 → 프로세스 종료 → 502
- `rpa/collector/browser.py` 를 Playwright **Async API** 로 재작성
  - 실행 옵션: `--no-sandbox` `--disable-setuid-sandbox` `--disable-dev-shm-usage` `--disable-gpu` `--no-zygote` `--renderer-process-limit=1` `--js-flags=--max-old-space-size=256` 등
  - `context.route("**/*")` 로 image·media·font·stylesheet·texttrack·manifest 차단 (`PLAYWRIGHT_BLOCK_TYPES`)
  - 브라우저·Playwright 는 `__aexit__` 의 try/finally 로, 여행사별 컨텍스트·페이지는 `Session` 종료 시 반드시 close, 여행사마다 `gc.collect()`
  - 페이지가 스크롤 중 스스로 이동(JS 리다이렉트)해도 수집 계속
- `rpa/run.py`: `collect_live_all()` 이 `asyncio.run` 으로 3곳을 차례로 수집(이벤트 루프가 도는 스레드에서는 별도 스레드)
- Dockerfile: `mcr.microsoft.com/playwright/python:v1.49.1-noble`, `MALLOC_ARENA_MAX=2`, 워커 1개, `pwuser` 실행, 문서 도구(pptx·TTS·ffmpeg)는 Windows 전용으로 이미지에서 제외
- 검증: pytest 77건 통과, 로컬 live 수집(리소스 차단 상태) 하나투어 79 · 모두투어 144 · 노랑풍선 116건
- 발표자료: 제목을 결과·수치 중심으로 수정, 13번 슬라이드를 노트북+스마트폰 목업으로 교체, PowerPoint COM 으로 전환·등장 애니메이션 추가(`office_com.pptx_animate`)
