# 04. 배포 (작업 1·3·4단계)

## 환경 변수

| 환경 | 설정 방법 |
|---|---|
| 로컬 | 프로젝트 루트 `.env` |
| EC2 | 서버 `~/nomadpick/.env` (docker compose `env_file`) |
| Render | 대시보드 > Environment > **Add from .env** 에 로컬 `.env` 내용을 복사하여 붙여넣기 |

| 변수 | 설명 |
|---|---|
| `DATABASE_URL` | **필수** TiDB: `mysql+pymysql://<user>:<pw>@gateway01.<region>.prod.aws.tidbcloud.com:4000/nomadpick` |
| `TEST_DATABASE_URL` | pytest 용(비우면 같은 클러스터의 `nomadpick_test` 자동 생성) |
| `DB_SSL` | TiDB TLS 사용(true) |
| `JWT_SECRET`, `JWT_EXPIRE_MINUTES` | JWT 서명 키 / 만료(60분) |
| `RPA_API_KEY` | `/api/v1/rpa/*` 인증 키 |
| `ADMIN_EMAIL/PASSWORD`, `DEMO_EMAIL/PASSWORD` | 최초 실행 시 생성할 계정 |
| `CORS_ORIGINS` | Netlify 등 허용 도메인 |
| `DATA_GO_KR_KEY` | 국토교통부 국내항공운항정보 서비스 키 |
| `RPA_SOURCE_MODE` | auto(기본) / live / sample |
| `RPA_USER_AGENT`, `PLAYWRIGHT_*` | 사람과 같은 브라우저 설정(UA, headless, channel, timeout, 미디어 차단) |
| `ENABLE_SCHEDULER`, `COLLECT_ON_STARTUP` | 내장 스케줄러 / 빈 DB 최초 수집 |
| `DOMAIN`, `DUCKDNS_SUBDOMAIN`, `DUCKDNS_TOKEN` | EC2 HTTPS 도메인 |

## 경로별 자동 배포

`main`에 push하면 변경된 파일에 따라 배포 대상이 나뉩니다.

| 변경 경로 | Netlify | Render | EC2 |
|---|---|---|---|
| `frontend/**`, `netlify.toml` | O | O | O |
| `backend/**`, `rpa/**`, `requirements.txt`, `Dockerfile` | - | O | O |
| `render.yaml` | - | O | - |
| `docker-compose.yml`, `deploy/**` | - | - | O |
| `docs/**` 등 | - | - | - |

| 대상 | 배포 방식 | 경로 제한 |
|---|---|---|
| Netlify | GitHub 연동 자동 배포 | `netlify.toml`의 `ignore`: `frontend/`·`netlify.toml`이 바뀌지 않으면 빌드 건너뜀 |
| Render | GitHub 연동 자동 배포 | `render.yaml`의 `buildFilter.paths` (대시보드에서 만든 서비스는 Settings > Build & Deploy > **Build Filters**에 같은 경로 입력) |
| EC2 | `.github/workflows/deploy.yml` | `dorny/paths-filter`로 서버 파일 변경 시 `pytest` → SSH `docker compose up -d --build` |

| GitHub Secret / Variable | 용도 |
|---|---|
| `EC2_HOST`, `EC2_USER`, `EC2_SSH_KEY` | EC2 SSH 접속 |
| `TEST_DATABASE_URL` | CI 테스트용 TiDB(`.../nomadpick_test`), 없으면 API 테스트 생략 |
| Variable `EC2_ENABLED` | `true`일 때 EC2 배포 |

## 1단계 - Netlify (프런트엔드)

1. Netlify > Add new site > Import from Git > `fsclass-n/nomadpick` 저장소, Branch `main`으로 연결합니다(연결 완료).
2. 빌드 설정은 `netlify.toml`이 자동 적용됩니다(`publish = "frontend"`, 빌드 명령 없음, `ignore` 경로 제한).
3. `frontend/` 변경이 `main`에 push되면 Netlify가 자동으로 배포합니다 → https://nomadpick.netlify.app

## 3단계 - Render (최종 도메인 1차)

1. Render에서 저장소를 연결합니다(연결 완료). Blueprint로 만들면 `render.yaml`(Docker, free, singapore, healthCheck `/api/v1/health`, autoDeploy on, buildFilter)이 적용됩니다.
2. Service > Environment > **Add from .env**에 로컬 `.env` 내용을 붙여넣습니다(`APP_ENV=render` 권장).
3. Settings > Build & Deploy > Auto-Deploy를 **On Commit**(또는 테스트 통과 후 배포하려면 **After CI Checks Pass**)으로 둡니다.
4. 확인: https://nomadpick.onrender.com/api/v1/health → `{"status":"ok","db":"tidb"}`
5. 참고: 무료 인스턴스(512MB)에서는 Chromium 수집 중 메모리가 부족할 수 있습니다. 이 경우 `auto` 모드가 sample로 대체하므로, live 수집은 EC2에서 운영하고 Render에는 `ENABLE_SCHEDULER=false`를 권장합니다.

## 4단계 - AWS EC2 (최종 도메인 2차)

1. EC2(Ubuntu 22.04, t3.small 이상)를 만들고 탄력적 IP를 연결한 뒤, 보안 그룹에서 22/80/443 포트를 엽니다.
2. DuckDNS에서 `nomadpick` 서브도메인을 EC2 IP로 지정합니다.
3. 서버에서 실행:
   ```bash
   curl -fsSL https://raw.githubusercontent.com/fsclass-n/nomadpick/main/deploy/ec2-setup.sh -o ec2-setup.sh
   bash ec2-setup.sh            # Docker 설치, 저장소 클론, DuckDNS cron
   cd ~/nomadpick && nano .env  # 로컬 .env 와 같은 형식으로 입력
   docker compose up -d --build # app(FastAPI+RPA+Chromium) + caddy(HTTPS 자동 발급)
   ```
4. 확인: https://nomadpick.duckdns.org/api/v1/health
5. Render와 EC2가 같은 TiDB를 쓰면 수집이 중복되므로 한쪽(Render 권장)에 `ENABLE_SCHEDULER=false`를 설정합니다.
