### [Part 1] PPT 발표 (00:00 ~ 03:00)

#### ⏱️ 00:00 ~ 00:20 | 슬라이드 1 — 표지
- 🎬 표지 슬라이드 (노마드픽 로고·팀명)
- 🖱️ 정면을 보듯 차분하게 시작, 첫 문장 후 1초 쉬기
- 🎙️
  > 안녕하십니까. 3조 조장 김길동입니다.
  > 저희 조가 만든 서비스는 **노마드픽**입니다.
  > 여러 여행사의 특가 상품을 자동으로 모아서, 내 취향에 딱 맞는 여행 상품만 골라 추천해 주는 서비스입니다.

#### ⏱️ 00:20 ~ 00:35 | 슬라이드 2 — 목차
- 🖱️ 목차 번호를 손가락으로 짚듯 포인터를 천천히 아래로
- 🎙️

  > 이어서 실제 화면으로 직접 사용하는 모습을 보여드리겠습니다.

#### ⏱️ 00:35 ~ 01:05 | 슬라이드 3 — 프로젝트 배경
- 🖱️ 83% → 70% → 5분 카드를 차례로 가리킨다
- 🎙️
  > 여행을 준비하면서 이런 경험 있으셨을 겁니다. 하나투어, 모두투어, 노랑풍선… 사이트를 하나씩 열어 특가를 비교하는 일이요.
  > 저희가 서른 분께 여쭤봤더니 **83%**가 비교하는 데만 30분 넘게 걸린다고 답하셨고, **70%**는 좋은 특가를 마감된 뒤에야 알았다고 하셨습니다.
  > 그래서 저희는 이 번거로운 비교를 **컴퓨터가 대신** 하도록 만들어, 30분 걸리던 탐색을 **5분 이내**로 줄이는 것을 목표로 했습니다.

#### ⏱️ 01:05 ~ 01:35 | 슬라이드 4 — 서비스 소개
- 🖱️ 표의 "선호 설정 → 오늘의 특가 → 맞춤 추천 → 상품 상세" 순서로 짚고, 오른쪽 페르소나 상자로 이동
- 🎙️
  > 사용 방법은 간단합니다. 가고 싶은 지역, 예산, 출발 달, 여행 기간 같은 **내 취향**을 한 번 입력하면,
  > 세 여행사의 특가를 한곳에 모아 보여드리고, 그중 나에게 가장 잘 맞는 **10개를 이유와 함께** 추천해 드립니다.
  > 예를 들어 "금요일에 출발하는 100만 원 이하 동남아 여행"을 찾는 직장인 정하늘 님 같은 분이 바로 저희 서비스의 주인공입니다.

#### ⏱️ 01:35 ~ 01:50 | 슬라이드 5 — 조 구성 및 수행 일정
- 🖱️ 표 → 아래 4단계 화살표를 왼쪽에서 오른쪽으로
- 🎙️
  > 저희는 네 명이 각자 화면, 데이터, 자동 수집, 서버를 나누어 맡았고,
  > 기획부터 설계, 개발, 배포까지 네 단계로 약 3주 동안 진행했습니다.

#### ⏱️ 01:50 ~ 02:10 | 슬라이드 6 — 시스템 구성 (비유)
- 🖱️ 구성도에서 브라우저 → 서버 → 데이터베이스 순으로 원을 그리듯 가리킨다
- 🎙️
  > 기술 구성은 **식당**에 비유하면 쉽습니다.
  > 여러분이 보시는 화면은 손님이 앉는 **홀**, 요청을 처리하는 서버는 **주방**, 모든 상품 정보가 저장되는 데이터베이스는 **냉장고**입니다.
  > 이 식당은 인터넷 위의 클라우드에 문을 열어 두어, 언제 어디서나 접속하실 수 있습니다.

#### ⏱️ 02:10 ~ 02:30 | 슬라이드 7·8 — 핵심 기술: RPA 수집
- 🖱️ 슬라이드 7의 BOT-01·02·03 세 줄을 짚고, 슬라이드 8 흐름도로 넘기며 화살표를 따라간다
- 🎙️
  > 이 서비스의 핵심은 **RPA**, 쉽게 말해 **로봇 비서**입니다.
  > 로봇 비서는 30분마다 세 여행사 홈페이지를 사람처럼 직접 둘러보며 특가를 적어 오고, 아침마다 국토교통부에서 국내선 항공편 정보도 받아 옵니다.
  > 이때 각 사이트의 규칙을 지키고, 너무 자주 방문하지 않도록 간격을 두어 예의 있게 정보를 모읍니다.

#### ⏱️ 02:30 ~ 02:45 | 슬라이드 9 — 데이터 정제 및 추천
- 🖱️ 위쪽 "추천 점수" 상자 → 아래 숫자 카드
- 🎙️
  > 여행사마다 "129만 원", "1,290,000원~"처럼 가격을 다르게 적기 때문에, 로봇이 이를 같은 기준으로 깔끔하게 정리합니다.
  > 그리고 내 취향과 얼마나 닮았는지, 할인은 얼마나 되는지, 예산 안인지를 점수로 매겨 추천 순위를 정합니다.

#### ⏱️ 02:45 ~ 03:00 | 슬라이드 10·11 — 문제 해결 및 테스트
- 🖱️ 슬라이드 10 첫 줄만 짚고 바로 11로 넘겨 97.4%·0.41초 카드 강조
- 🎙️
  > 개발 중에는 한 여행사가 로봇의 방문을 막는 문제도 있었지만, 사람과 같은 방식으로 방문하도록 개선해 해결했습니다.
  > 그 결과 수집 성공률 **97.4%**, 화면 응답 **0.4초**로 목표를 모두 달성했습니다.

- 🖱️ ① 상단 파란 영역의 "수집 상품·여행사·최근 수집" 숫자 → ② 지역 칩 **[동남아]** 클릭 → ③ 예산 **100만 원 이하** 선택 → ④ 정렬 **낮은 가격순** → ⑤ 검색창에 `다낭` 입력 후 Enter → ⑥ 카드 하나에 포인터 올리기(살짝 떠오르는 효과) → ⑦ 검색어 지우고 아래로 스크롤해 **[더 보기]**

  > 도시 이름으로 바로 찾을 수도 있습니다. 다낭을 검색하면 세 여행사의 다낭 특가가 한 번에 나옵니다.
  > 카드마다 할인율, 여행사, 출발 날짜, 가격이 한눈에 정리되어 있어 사이트를 옮겨 다닐 필요가 없습니다.

## 4. 녹화·압축 설정 (GitHub 업로드용)

| 항목 | 권장값 |
|---|---|
| 해상도 / 프레임 | 1920×1080 (또는 1280×720) / 30fps |
| 코덱 / 포맷 | H.264(video) + AAC(audio) / MP4 |
| 목표 용량 | **90MB 이하** (GitHub 단일 파일 한도 100MB, 50MB 초과 시 경고만 표시) |
| 비트레이트 | 10분 기준 영상 약 1.0~1.1Mbps + 음성 96~128kbps → 약 80~90MB |

OBS 녹화 설정: 출력 → 녹화 → 형식 `mp4`(또는 `mkv` 녹화 후 리먹스), 인코더 x264, 레이트 컨트롤 `CBR 2500kbps`(고화질로 녹화한 뒤 아래 스크립트로 압축).

### 압축 (FFmpeg 2-pass, 목표 용량 자동 계산)

```bash
# FFmpeg 설치(최초 1회): winget install Gyan.FFmpeg
.venv\Scripts\python.exe docs\tools\compress_video.py 원본.mp4 docs\video\nomadpick_demo.mp4 --target-mb 90
```

- 영상 길이를 읽어 목표 용량에 맞는 비트레이트를 계산하고, H.264 2-pass + AAC 128kbps, 최대 1920×1080·30fps로 인코딩한다.
- 결과가 95MB를 넘으면 `--target-mb 80` 또는 `--height 720`으로 다시 실행한다.

---

### 자동 제작 (사람 녹화 대신)

```bash
.venv\Scripts\python.exe docs\tools\make_video.py --base http://127.0.0.1:8000 --target-mb 85
```

- 이 문서의 장면별 나레이션(`>` 줄)을 Edge 한국어 남성 음성(`ko-KR-InJoonNeural`)으로 읽어 TTS 생성
- PPT 슬라이드는 1920×1080 PNG 로 내보내 나레이션 길이만큼 표시(슬라이드 13 생략)
- 웹 시연은 Playwright 가 대본 동선(일반 회원 가입·선호·추천·상세·마이페이지 → 관리자 로그인·대시보드·로그·수동 실행·리포트)을 자동 조작하며 녹화, 노란 원으로 커서 위치 표시
- 장면별 음성과 화면을 맞춰 합친 뒤 목표 용량으로 2-pass 압축 → `docs/video/nomadpick_demo.mp4`
- 대본 문장을 고치면 해당 장면만 TTS 를 다시 만들고 영상 전체를 재조립한다 (작업 파일: `docs/tools/out/video/`)

## 5. GitHub 업로드

1. 압축한 영상을 `docs/video/nomadpick_demo.mp4`로 저장 → 커밋·푸시 (100MB 미만 필수)
2. README 상단 썸네일(`docs/md/images/thumbnail.png`)을 누르면 영상 파일로 연결된다. GitHub 파일 화면에서 바로 재생·다운로드할 수 있다.
3. README 안에서 바로 재생되는 플레이어가 필요하면: GitHub 웹에서 README 편집 → 영상 파일을 끌어다 놓기(무료 계정은 10MB, 유료 계정은 100MB까지) → 생성된 `https://github.com/user-attachments/assets/...` 주소를 README에 붙여 넣는다. 10분 영상은 보통 10MB를 넘으므로, 무료 계정이면 YouTube(일부 공개) 링크를 함께 적어 두는 것을 권장한다.
4. 슬라이드 이미지(`docs/md/images/slides/`)와 시연 화면(`docs/md/images/`)은 README 갤러리에 이미 연결되어 있다. PPT를 수정하면 슬라이드 이미지를 다시 내보낸다(파워포인트 > 파일 > 내보내기 > PNG, 또는 `docs/tools/build_docs.py` 실행 후 재내보내기).
