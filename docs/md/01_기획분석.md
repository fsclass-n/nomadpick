# 01. 기획/분석

## 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 조 | 3조 (4명) - 김길동(조장), 박미금, 이오리, 홍기흥 |
| 주제 | 개인 맞춤형 여행상품 추천 |
| 프로젝트명 | NomadPick (노마드픽) |
| 한 줄 소개 | RPA로 여러 여행사(하나투어·모두투어·노랑풍선)의 특가 정보를 수집하고, 사용자 선호도에 따라 DB로 정리하여 웹에서 맞춤 추천 |
| 저장소 | GitHub `nomadpick` (backend / frontend / rpa / docs) |

## 역할 분담

| 이름 | 역할 | 주요 담당 |
|---|---|---|
| 김길동 (조장) | PM · 백엔드 · 배포 | FastAPI REST API·JWT 인증, Docker·Render·EC2 배포, GitHub Actions |
| 박미금 | DB · 데이터 처리 · 추천 | TiDB 스키마(10개 테이블), pandas 정제, scikit-learn 추천, 엑셀 리포트 |
| 이오리 | 프런트엔드 · UI/UX | HTML5·CSS3·Vanilla JS·Bootstrap 5 화면 8개, Plotly 차트, Netlify 배포 |
| 홍기흥 | RPA · 데이터 수집 | Playwright·BeautifulSoup4 수집기 3종, 국토교통부 API 연동, 스케줄러 |

## 요구사항 요약

### 기능 요구사항 (14건)

| ID | 요구사항 | 우선순위 | 구현 위치 |
|---|---|---|---|
| FR-01 | 회원가입·로그인(JWT, 1시간 만료) | 상 | `backend/app/routers/auth.py` |
| FR-02 | 선호 설정(지역·예산·출발월·기간·테마·동행) | 상 | `routers/preferences.py`, `frontend/preferences.html` |
| FR-03 | 오늘의 특가 목록(필터·정렬·페이지, 수집 시각) | 상 | `routers/products.py`, `frontend/index.html` |
| FR-04 | 상품 상세(가격 추이 30일, 원문 링크) | 상 | `frontend/product.html` |
| FR-05 | 맞춤 추천 Top 10 + 추천 사유 | 상 | `services/recommend.py` |
| FR-06 | 관심 상품(가격 하락 배지) | 중 | `routers/favorites.py` |
| FR-07 | 추천 결과 엑셀 다운로드 | 중 | `services/excel.py` |
| FR-08 | 특가 수집(여행사 3곳, 30분 주기) | 상 | `rpa/collector/` |
| FR-09 | 정제·적재(중복 제거, 표준화, upsert) | 상 | `rpa/cleaner/normalize.py`, `services/ingest.py` |
| FR-10 | 공공데이터 수집(국토교통부 국내항공운항정보) | 중 | `rpa/public_data/molit_flight.py` |
| FR-11 | 가격 이력 저장(스냅샷) | 상 | `price_snapshots` 테이블 |
| FR-12 | 일일 엑셀 리포트(Seaborn·Matplotlib 차트) | 하 | `rpa/report/daily_report.py` |
| FR-13 | 관리자 수집 모니터링 | 중 | `routers/admin.py`, `frontend/admin.html` |
| FR-14 | 국내 상품 항공편 정보 반영 | 중 | `services/products.py::flights_for` |

### 비기능 요구사항 (6건)
- 성능: 목록·추천 API 평균 1초 이내
- 신뢰성: HTTP 오류 3회 재시도(2·4·8초), 파싱 실패율 20% 초과 시 WARN
- 준법·윤리: robots.txt 확인, 요청 간격 2초, 사실 정보만 저장, 원문 링크 제공
- 보안: bcrypt, JWT, RPA 전용 키(X-RPA-KEY), 비밀 정보는 `.env` 하나로 관리
- 사용성: Bootstrap 5 반응형(375px ~ PC), 모바일 필터 오프캔버스
- 운영: main 병합 시 자동 배포, 수집 실행 로그 저장

## 기술 스택

| 구분 | 기술 |
|---|---|
| Frontend | HTML5, CSS3, Vanilla JavaScript, Bootstrap 5, Flexbox, Plotly.js |
| Backend | Python 3.11.9, FastAPI, SQLAlchemy 2, PyMySQL, PyJWT, bcrypt, APScheduler |
| Database | TiDB Cloud (MySQL 8.x 호환, TLS) - 로컬 테스트 포함 (SQLite 미사용) |
| Cloud / External | 국토교통부_(TAGO)_국내항공운항정보 API |
| Deploy | Netlify, Render(Docker), AWS EC2(Docker Compose + Caddy), GitHub Actions |
| RPA / Data | Playwright, BeautifulSoup4, Requests, pandas, NumPy, scikit-learn, Seaborn, Matplotlib, Plotly, openpyxl |
| 환경 | `.venv`, 단일 `requirements.txt`, `.env`(로컬·EC2) / Render 환경 변수 붙여넣기 |

## 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 여행사 특가 목록이 JavaScript로 렌더링되거나(하나투어·노랑풍선·모두투어) 봇형 요청이 차단됨(모두투어 Access Denied) | Playwright로 일반 사용자의 Chrome과 같은 조건(UA·로케일·자동화 흔적 제거·사람 같은 스크롤)으로 렌더링 후 수집, 셀렉터는 `selectors.json`으로 분리, 실패 시 `auto` 모드가 같은 파서로 sample 페이지 수집 |
| Render 무료 인스턴스 슬립 | 헬스 체크를 두고, 프런트엔드는 오프라인 데모 데이터로 대체 표시 |
| 비밀 정보 노출 | `.env`는 저장소에서 제외, EC2는 서버 `.env`, Render는 대시보드 환경 변수 |
